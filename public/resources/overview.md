# 课程总纲

## 一、课程定位

**课程名称：领航者·AI 产品创造与全栈实践**

**课程主张：先找准一个问题，用 AI 协助实现，再用工程方法证明它可用。**

适合希望完成第一件可持续迭代作品的大学生、跨专业学习者，以及有办公软件经验但缺少编程项目经验的成人学习者。入门要求为能管理文件、安装应用、使用浏览器和输入英文符号；不要求已有 Java 或 Python 基础。课程默认使用电脑，不以手机独立完成开发为目标。

课程结束后，学员能够完成小规模 Web 应用的需求、页面、资料持久化、接口、权限验证、AI 增强和交付说明。这个结果不等同于熟练掌握原全栈课程的全部企业技术，也不承诺就业或商业收入。

本方案按“两套课程”指向此前已确认的领航者与 AI 创造者资料设计；“骨架”采用它们现有的阶段、章节与课内教学结构。未发现单独指定的新课程骨架文件，因此本次建立了一套新的八阶段骨架。

## 二、六项可观察的毕业能力

| 能力 | 需要提交的证据 |
|---|---|
| 定义问题与范围 | 真实观察记录、一页需求、功能取舍和验收条件 |
| 有效开展 AI 协作 | 至少三份任务单、一次生成结果审查和一次错误修复记录 |
| 理解并实现核心数据流 | 能解释浏览器—接口—业务规则—数据库之间的数据传递 |
| 保证关键行为与权限 | 正常、异常、跨账户、数据恢复和回归验证记录 |
| 设计有依据的 AI 功能 | 结构检查、来源核对、故障回退和固定题集评测 |
| 独立迁移并交付 | 新场景中的业务改动、干净环境复现、作品说明与现场答辩 |

## 三、贯穿项目：研习站

小禾在学习不同项目时，资料散落在收藏夹和笔记里。研习站让使用者围绕一个学习项目保存资料、记录备注、检索旧内容，并对主动选择的笔记生成摘要与带来源的回答。

核心路径：**创建项目 → 保存资料 → 再次找回 → 阅读或整理 → 根据来源核查 AI 建议。**

第一版不做社区、支付、实时协同、爬取全网资料或自动访问用户粘贴的网址。课程资料由学员手动输入或使用虚构数据，避免把内容采集与复杂网络抓取变成前置门槛。

| 版本 | 新增能力 | 学习价值 |
|---|---|---|
| V0 | 问题卡、范围卡、纸面原型 | 先明确做什么、为什么做 |
| V1 | 静态结构与内存交互 | 理解页面、事件和数据 |
| V2 | 本地保存、搜索、版本记录 | 处理状态、边界与恢复 |
| V3 | Python 数据处理与接口契约 | 建立服务端与输入校验思维 |
| V4 | 数据库及完整接口闭环 | 从单页样机走向有状态应用 |
| V5 | 多用户权限、测试、备份 | 处理真实使用中的错误与隔离 |
| V6 | 摘要、引用问答、受控工具 | 将 AI 变成可检查的产品能力 |
| V7 | 可复现交付、迁移与答辩 | 证明学员可以独立继续开发 |

## 四、学时与进度

全部“小时”按 60 分钟计。48 讲 × 90 分钟 = 72 小时；8 个阶段项目 × 3 小时 = 24 小时；总计 **96 小时**。建议 12 周、每周 8 小时。

## 五、技术路线与选择理由

主线为 **HTML/CSS → 原生 JavaScript → Python → SQLite → HTTP 接口 → AI 适配器**。先让初学者看到完整数据流，再按需要学习框架。

- HTML/CSS/JavaScript 保留原领航者的基础训练，让学员能解释并修改 AI 生成的页面。
- Python 承接原领航者 Agent 阶段与 AI 创造者增值方向，统一数据处理、后端和 AI 练习，减少在主线中来回切换后端语言。
- SQLite 用于单机小规模课程练习。明确其存储和并发边界，再在进阶线迁移到服务型数据库。
- Web 路由可由讲师在开班前选定并锁定一个轻量 Python 框架；不要求学员自行比较全部框架。课稿教授契约、路由、校验和数据访问，不写可能过时的界面点击路径。
- 模型通过适配器接入。无模型账号时使用明确标注的模拟器完成界面和故障练习；真实效果评测须使用真实调用结果。

授课前需补定当前班级的解释器、框架版本、依赖锁定文件、认证组件及可用模型服务，并在教学环境试跑。本文不把未锁定的具体软件版本或供应商额度描述为已验证可用。

## 六、从两套课形成新结构

| 原资料优势 | 新课中的安排 | 重构原因 |
|---|---|---|
| AI 创造者先作品、后概念，需求与原型清楚 | 第 1 阶段先验证需求，第 2 阶段做首件作品 | 降低入门阻力，并让后续知识有具体用途 |
| 领航者的编程、数据、接口和工程体系 | 第 2—6 阶段按作品需要逐次补齐 | 避免只有提示词、却不能排错与维护 |
| 两套课均讲 AI 协作 | 第 1 阶段建立任务单，后续每阶段应用 | 去重并统一交付与验收方法 |
| AI 创造者的概念、练习、测验结构 | 每讲统一为讲解、演示、动手、检查、复盘 | 将“看过”转为可检查能力 |
| 领航者的 Agent/RAG 主题 | 第 7 阶段建立有来源、有权限的 AI 能力 | 补充固定评测集与失败回退 |
| 部署、作品集与进阶方向 | 第 8 阶段交付、迁移、答辩 | 证明可以独立继续，而非只完成跟做 |

## 七、进阶路径（不计入本课程 96 小时）

下面是后续课程规划，不是本包已编写的额外课稿。

| 方向 | 先补能力 | 建议迁移项目 | 完成证据 |
|---|---|---|---|
| Java 企业全栈 | Java 核心、集合异常、Maven、Spring Boot、MySQL、测试与认证 | 将研习站后端迁移为 Java 实现，保持接口契约 | 前后端无需改契约即可联调，原回归用例通过 |
| 前端工程 | TypeScript、组件设计、路由、状态管理、可访问性 | 将原生页面迁移为组件化应用 | 复用组件有明确输入输出，键盘与窄屏验证通过 |
| AI 应用工程 | 向量检索、检索评测、工具协议、可观测性与成本管理 | 扩大资料规模并比较检索方案 | 固定题集、质量与成本对比、越权检查 |
| 服务与架构 | Linux、容器、持续集成、缓存、消息队列、容量测量 | 对真实瓶颈做一次有证据的优化 | 同一负载下前后测量和故障恢复记录 |

微服务、Kubernetes、支付、微调和强化学习均不作为零基础主线必修。需要时另建先修链与实训，不仅增加名词介绍。
