# 项目任务书与评分标准

## 一、统一业务约定

产品名：研习站。核心用户：需要围绕学习项目保存、整理和找回资料的人。

资料由用户主动输入；保存的网址只作为链接展示，不自动请求远程网页。AI 摘要只处理用户选择的笔记文字，课程不要求抓取任意链接。

| 对象 | 核心字段 | 规则 |
|---|---|---|
| Project | id、name、owner_id、created_at | 名称去掉首尾空白后非空；owner_id 从可信身份确定 |
| Record | id、project_id、title、url、note、read_later、version、created_at、updated_at | 标题必填；同名允许；id 唯一；修改需对应版本 |
| Summary | id、record_id、source_version、text、model_label、created_at | AI 文本与原文分开；原文改动后旧摘要标为待更新 |
| Citation | record_id、片段标识、来源版本 | 必须对应本次有权限检索到的资料片段 |

课程统一标题上限为 80 个 Unicode 码点：Python 用 len(text)，JavaScript 可用 Array.from(text).length。本讲次 L13 先观察 JavaScript length 的行为，到 L22 统一前后端规则并修订前端。HTML maxlength 使用另一种计数语义，不能仅靠它落实最终规则；对最终表单以显式业务校验为准。

URL 是可选字段，允许明确的 http/https 链接；空值不影响保存。标题匹配忽略大小写并去掉查询首尾空白。列表按 created_at、id 形成稳定次序。日期在服务端统一保存可比较格式，界面再转换为显示格式。

前端 readLater 与后端 read_later 的映射应集中处理；也可以全栈统一命名，但须更新契约和样例，不能混用后依靠猜测。

## 二、接口契约基线

| 方法与路径 | 输入 | 成功结果 | 主要失败 |
|---|---|---|---|
| GET /api/health | 无 | 200，基本可用状态 | 服务不可用 |
| POST /api/projects | name | 201，项目对象 | 400 输入无效；401 未认证 |
| GET /api/projects | 当前会话 | 200，当前用户项目数组 | 401 未认证 |
| GET /api/records | projectId、q、page、pageSize | 200，data 数组与分页信息 | 400 参数无效；403 无权访问 |
| POST /api/records | projectId、title、url、note、请求标识 | 首次 201，记录对象；防重命中 200，原结果 | 400 输入错误；403 无权限；409 同标识不同内容 |
| PATCH /api/records/{id} | 可修改字段及 version | 200，新版本记录 | 400 输入错误；403 无权限；404 不存在；409 版本冲突 |
| DELETE /api/records/{id} | 当前会话 | 204，无响应正文 | 403 无权限；404 不存在 |
| POST /api/records/{id}/summary | 当前会话、所需生成选项 | 200，摘要及来源版本 | 403 无权限；429 限流；502 上游失败；504 超时 |
| POST /api/ask | projectId、question | 200，answer、citations、evidenceStatus | 400 无效输入；403 无权限；429 限流 |

为了防止资源存在性泄露，也可统一以 404 表示不可访问资源，但全项目必须一致，测试按选择的约定执行。第 5 阶段暂为回环地址上的单用户练习，第 6 阶段加入真实认证与授权之后才具备受控多人内测条件。

分页规则：page 从 1 开始，pageSize 默认 20，上限 100；非法值返回 400。超出末页返回成功空数组。错误体形如 `{"error":{"code":"INVALID_TITLE","message":"请填写资料标题","fieldErrors":{"title":"不能为空"}}}`。前端对 204 不尝试解析 JSON。

## 三、八次阶段关卡

每关 3 小时建议安排：整合与检查 90 分钟、演示互评 45 分钟、修订和记录 45 分钟。前面逐讲动手已有实现，本阶段不要求从零重做全部功能。

### 关卡 1：项目立项

交付问题证据、一页需求、范围卡、六条验收条件和三张原型。

通过条件：能指出明确用户和场景；假设与事实分开；核心路径闭合；至少一个功能被有理由地排除；另一人能在原型上完成路径。访谈不足时可以标注自我观察，不能虚构他人反馈。

常见补修：范围过大则回到 L03；验收只写形容词则回到 L04；操作入口混乱则回到 L06。

### 关卡 2：网页样机

交付语义化页面、统一样式、三种视口记录、可新增的内存资料列表和两份故障修复记录。

通过条件：表单有标签；键盘可到达主要操作；360 像素视口无主流程横向溢出；资料标题作为普通文本显示；新增后列表变化。刷新清空在此阶段允许，但须明确标注。

常见补修：不会解释结构回 L08；样式堆叠回 L09；事件与数据混淆回 L11。

### 关卡 3：本地可用版

交付本地持久化、搜索、稍后读、JSON 导入导出、旧数据迁移和三次有意义的版本提交。

通过条件：刷新后记录保留；同名记录独立操作；坏 JSON 不覆盖原数据；导出再导入保持约定字段；缺少新增字段的旧数据可处理。每个数据破坏场景在测试副本中操作。

常见补修：标识混乱回 L14；导入损坏回 L16；新增功能破坏旧功能回 L18。

### 关卡 4：服务端规则包

交付可运行的 Python 资料审计程序、校验函数、错误分支、规范化输出副本和资料接口契约。

通过条件：空列表可处理；重复 id 被报告；重复标题不误删；字段类型错误得到明确提示；原文件不被覆盖；另一人能从契约推断请求与响应。至少六个不同校验输入有实际结果。

常见补修：运行目录混乱回 L19；类型错误回 L20；函数不可独立验证回 L22。

### 关卡 5：数据库全栈版

交付数据库结构、四类 CRUD 接口、事务导入、前端联调与分页、查询测量说明。

通过条件：新增后刷新可读；无效项目不能插入资料；参数化 SQL 正确处理引号；导入中途失败无部分残留；未知 id 与非法输入行为符合契约；分页边界明确。查询优化按测量质量评价，不要求虚构加速。

常见补修：数据关系错误回 L25；整批导入留下残余回 L27；只处理网络异常回 L29。

### 关卡 6：可信内测版

交付权限矩阵、身份方案说明、至少十二条测试、重复与冲突处理、备份恢复及小样本试用记录。

通过条件：B 无法读改删 A 的资料；模拟身份没有混入正式部署配置；密钥不在前端；重复请求不会创建两条记录；过期版本修改可识别；备份在独立位置成功恢复。用户试用记录区分实际操作与建议。

此关的越权、真实密钥暴露和未受控数据破坏属于阻断项，应修复后重新验收，不能用页面美观抵分。

### 关卡 7：可核查的 AI 版

交付摘要适配器、结构校验、来源问答、只读工具演示与二十题评测表。

通过条件：模型不可用时基本资料功能可用；模型输出不直接覆盖原文；引用可追溯；无资料时表达证据不足；不读取其他用户资料；工具调用受参数与步数限制。

真实 AI 路线：记录实际服务与配置，至少 16/20 题通过，同时越权及未授权写入为零。模拟路线：可检查接口和故障设计，但不能获得“真实 AI 效果已验证”的结论；评测表中的效果项标为待真实调用补验。两条路线都可提交课程学习档案，成绩须注明验证范围。

### 关卡 8：毕业交付

交付可复现包、版本与回退说明、运行观察记录、独立题目增量、作品说明与答辩。

通过条件：同伴按文档能启动；测试环境与秘密配置明确；能演示一次恢复；新题目增加真实业务规则；现场能解释数据流并完成一个小改动。线上作品须另有实际访问与基本运行检查证据，本地包不能标作已上线。

## 四、毕业评分（100 分）

| 维度 | 分值 | 得分依据 |
|---|---:|---|
| 问题与产品设计 | 15 | 证据 5；范围取舍 5；验收与原型 5 |
| 核心功能与数据闭环 | 25 | 页面与交互 5；保存检索 8；接口与模型 6；数据边界 6 |
| 质量与权限 | 20 | 跨账户隔离 8；回归与故障 6；备份恢复 6 |
| AI 功能与评测 | 15 | 适配与故障处理 4；结构及引用检查 4；真实评测证据 7 |
| 可复现交付 | 10 | 文档与新环境启动 6；版本及回退 4 |
| 独立迁移与解释 | 15 | 新规则及实现 6；现场改动 5；取舍与限制 4 |

评分原则：对应项完整且有证据得满分，部分完成且可复现得部分分，没有证据或不能运行不得实现分。模拟路线的“真实评测证据”7 分保留待补，不用模拟成功冒充真实成功。

建议结课门槛：总分至少 70，八关材料齐全，核心资料路径可用，质量与权限不少于 12/20，独立迁移与解释不少于 8/15，无未修复的阻断项。真实 AI 未补验者在结课记录中注明“AI 接口与模拟流程完成，真实效果待验证”。公开部署不是强制结课条件。

## 五、答辩抽签题

1. 资料保存超时后重试，如何知道没有重复？
2. 读取另一用户资料编号，哪一层阻止访问？请演示。
3. 输入空白标题、超长标题和表情，如何保持前后端规则一致？
4. 关闭模型适配器，哪些功能仍应正常？
5. 原文更新后旧摘要如何提醒用户？
6. 为资料增加一个筛选规则，需要改哪些文件和测试？
7. AI 引用了一个不存在的资料 id，系统如何处理？
8. 在新目录恢复备份，如何核对确实恢复成功？

允许使用自己的笔记和 AI；须解释采用的方案并亲自核对运行结果。考核重点是判断、验证和修订能力。
